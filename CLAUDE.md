# Reset Program: guidance for changes

Static site on GitHub Pages (`main`, root) with a Supabase database. Plain HTML/CSS/JS, no build step. `index.html` is the student laptop view, `teacher.html` the dashboard. Settings in `js/config.js`, student-facing words in `js/content.js`, electives in `js/modules/`, database in `supabase/schema.sql`. See `README.md` for how the program runs.

## Decisions made by the staff

- **No personal information in the database or the repo.** Students are random 8-character codes; staff keep the code-to-name list offline. Never add name or email fields. Module written answers are stored at staff request (see below); ask before storing any other free text. The certificate name is typed on the page and never saved.
- **Students don't log in.** Their code is the key, used only through the `student_*` database functions. Teachers log in with Supabase Auth and must be listed in `public.staff`.
- **Modules, everywhere:** everything in the day is a module. **Group modules** (a staff member with the group) and **individual modules**, which are either **independent** sessions (on the laptop) or **teacher-led** sessions (one-on-one with a staff member). Use these words on both sites (`RP.KIND_LABEL`). The plan editor is called the **Daily schedule**.
- **Day shape:** 10 sessions, each ending with a school bell or mid-period (P1 8:20–9:23, P2 –10:26, B1 10:26–10:56, P3 –11:59, P4 –1:02, B2 1:02–1:32, P5 –2:35). Session 1 (8:20–8:50) is usually the whole-group morning session (staff can drag **Morning session** to a later time for a late arrival or a return meeting; 8:20 then becomes free for anything): social story, then the morning check-in (ready-to-learn traffic light, have I had breakfast / pen / uniform / bag / lunch / other food, then the survey); the board shows the traffic light and anything they don't have. Session 10 (2:03–2:35) is the whole-group afternoon debrief with the afternoon survey. Sessions 2–9 are half-periods. The breaks are called **B1** and **B2** (not recess and lunch); students go as normal and come back to **the Hub** (the room's name).
- **New students start with empty independent sessions** (`RP.DEFAULT_ELECTIVES` is empty) for staff to fill in; group modules come from the rotation.
- **Two-day rotation:** the room alternates group-session rotations, so students on Day 1 and Day 2 share group sessions. Every core group session must be done within the student's two days, so **each group session and each independent module must stand alone**: there's no guaranteed order.
- **Group modules** (max 5 students, 1 staff member; run sheets in `RP.GROUP_SESSIONS[].guide`, slides in `.slides` for the Present view): Rotation A: T-RED Values, RIOT 1, Wellbeing, Chain Analysis. Rotation B: Student Code of Conduct, RIOT 2, Classroom Expectations, Self-Regulation. Both at 8:50, 9:55, 11:27 and 12:30. **Every guide follows the Thomas Reddall Lesson Routine** (`RP.LESSON_ROUTINE`; poster at `img/lesson-routine.jpg`): entry, Do Now, learning intention and success criteria, explicit teaching, brain break, application, recap, exit. Make them interactive (butcher's paper, discussion, card sorts). T-RED uses discussion and butcher's paper but no games (those were for orientation day). Classroom Expectations teaches the lesson routine itself. RIOT, Wellbeing and Self-Regulation will be rebuilt from the RIOT materials when staff upload them; RIOT worksheets from the suspension booklet will also become independent modules. Use made-up examples; never ask a student to share their own incident. Staff can drag a different group module into a slot, but only after an "Are you sure?" confirm. **RAGE Recap** is an optional (not core, not in a rotation) group module staff swap in when it suits the group; it's an outline until the school's RAGE materials are added.
- **Other sessions:** staff can drag **Other** into a slot and type what it is (kind `free`, activity `custom`, the typed name in `title`). Students see the name and are told they won't need their laptop. The staff ticks it done.
- **Teacher-led sessions** are dragged into a slot by the teacher (kind `one_to_one`, `RP.INDIVIDUAL_SESSIONS`): Day 1 **Teacher-led: My Reset Plan** (was "Review of plans, goals and Sentral"); Day 2 **Teacher-led: My Return Plan**; **Return from suspension meeting**; classwork and assessment check-in; learning and support check. One student at a time: the daily schedule and board warn about clashes. The staff member is whoever is on the run sheet's staffing for that session (`public.staffing`). The two plans each have an **independent** version the student does first on the laptop (`reset-plan`: the Behaviour Chain Analysis worksheet from SocialWorkersToolbox.com, wording unchanged as its licence requires, printable copy in `resources/`; `module-6`: My Return Plan); the teacher-led page shows those answers once submitted. Each has a page showing the student's relevant surveys and module answers; My return plan and the return meeting print a Return to Class Plan to sign (nothing typed there is saved). Session notes and testing results stay in Sentral and other school systems, not here.
- **Movement breaks** are not planned into the day. Each group module has a brain break built in, and written movement-break resources (the `move-*` entries) sit on the Session guides page for staff to pull out when students need a break.
- **Surveys** (`js/surveys.js`): start and end of both days (`d1am`, `d1pm`, `d2am`, `d2pm`) plus a follow-up 4–6 weeks after return (a "followup" program that reactivates the code for the survey only). Same 10 rating statements in each, from the school's TRHS survey. Surveys done at the same time must take the same time (both mornings match, both afternoons match). Wording asks students not to give identifying information. Ratings go in the session's `result` (`survey`, `ratings`, `total`), written answers in `state.responses`; the Reports page and downloads use them.
- **Pause:** a program can be paused (student absent); the code shows a "paused" screen until resumed.
- **Numeracy** is two half-hour modules, `numeracy-day1` and `numeracy-day2`. Levels 1–4 are Years 3–6 from The Daily Dash (`jasefreters/mathswarmup`): `tools/dash-numeracy.js` converts its picture-free questions into `js/modules/numeracy-dash.js` (12 per level per day; rerun it when the Dash grows). Levels 5–6 (Years 7–8, 9–10) are written in the module files. Credit the NSW Department of Education (CC BY 4.0).
- **Suspension Booklet** (`suspension-booklet`): students pick a subject, type the page or question and their answer, and mark subjects started or finished; the day certificate lists them. Each year's booklet is split into one PDF per subject in `booklets/yearN/` **without the teacher answer sheets**; students can also use a paper copy or their own booklet. Only Year 7 so far.
- **Reading levels 1–5** (Stages 1–5, labelled "Level" not "Stage") are **only in the Literacy module** (Numeracy's levels are year levels, above); other modules use their standard text. Nothing reads aloud automatically, but every page has a Read aloud button. Students can look up any word with **What does it mean?** in the top bar (select a word, or type one; only the word is sent to a free dictionary).
- **Chromebooks:** students log in as themselves and use Chrome. They can't print, so certificates and answers offer Save as PDF and Email.
- **Videos** must suit students (Years 7–10, mostly 7–8), not adults. Staff should preview each one before students use it; every video item has a written summary in case it won't play.
- **Electives are done independently** on the laptop, so the teacher is free for 1:1s. Group sessions tell students to put the laptop aside; the teacher ticks them off.
- A finished elective can't be redone unless the teacher clicks **Let them redo**.
- **Records kept for returning students:** electives finished, level and score, group sessions done.
- **Written answers go to the teacher once submitted.** `write` and `select` answers stay on the laptop while the student works, then are saved with the module when it's finished (`sessions.state.responses`), locked, and shown on the student's certificate page and the teacher's record page. Students are told their teacher will read them. Prompts stay optional, as the staff notes ask not to force disclosure.
- **Certificates are given at the end of each day, not each module.** The day certificate lists every module finished that day (group, independent, teacher-led). Students get it after the afternoon survey and can reopen it from their plan; teachers reprint it from the record. Finishing a module shows the student's answers to save or email. Names are typed at print time and never saved.
- **Independent modules** are as interactive as possible and vary activity types across the day (sort, order, match, select, rating, sliders, body map, choose-your-path stories, phrase tiles, breathing, chain-writing, video). `module-1`…`module-5` are the reflection halves of the school's module documents (Module 6 is now the teacher-led My return plan); `my-chain`, `tred-values` and `code-of-conduct-check` are built from the school's Chain Analysis video, T-RED presentations and the Department's Student Code of Conduct. My Reset Plan and My Return Plan (independent halves of the teacher-led plans), Suspension Booklet, Numeracy Day 1 and Day 2. Staff-chosen extras: Say It Better, Online Conflict and Social Media, Restorative Conversation Prep, Growth Mindset, Goal Builder, Healthy Habits Check, Asking for Help, Study Skills, Attendance and Truancy. **Literacy is one half-hour module** (`literacy.js`) with levels 1–5, built from the reading, vocabulary, spelling and grammar question banks in `literacy-*.js` (hidden as separate modules). Keep the school's wording when editing modules. Staff can preview any independent module (every page, with answers) from the daily schedule, board and Session guides.
- **Branding:** colours from the school's colour hierarchy (maroon, light blue and dark navy primary; royal blue secondary; greys). The colour hierarchy image is a palette guide only: **never use it as a logo or picture on the site.** The logo is the sun rising over an open book (`RP.logo`, drawn as SVG). Motto: "Focusing on our Future" (footer, certificates, Present view). Navy top bar; dashed sunbursts (`img/sunburst.svg`) as soft background decoration.

## Before publishing

- Run the flows in a browser with `?demo=1` (teacher creates a student, plans the day, student completes an elective and gets the certificate). Check every answer in new elective content yourself.
- Changes to the database go in a new SQL file under `supabase/` (e.g. `update-2.sql`) for staff to run in the SQL Editor; keep `schema.sql` as the full current setup. The site must keep working before an update is run (see `withV2` in `js/api.js`).
- Publishing: commit to `main` on `jasefreters/TRHS`. Bump the `?v=` number on every script and stylesheet tag in `index.html` and `teacher.html` so browsers load the new files straight away.
