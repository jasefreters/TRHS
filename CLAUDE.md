# Reset Program: guidance for changes

Static site on GitHub Pages (`main`, root) with a Supabase database. Plain HTML/CSS/JS, no build step. `index.html` is the student laptop view, `teacher.html` the dashboard. Settings in `js/config.js`, student-facing words in `js/content.js`, electives in `js/modules/`, database in `supabase/schema.sql`. See `README.md` for how the program runs.

## Decisions made by the staff

- **No personal information in the database or the repo.** Students are random 8-character codes; staff keep the code-to-name list offline. Never add name or email fields. Module written answers are stored at staff request (see below); ask before storing any other free text. The certificate name is typed on the page and never saved.
- **Students don't log in.** Their code is the key, used only through the `student_*` database functions. Teachers log in with Supabase Auth and must be listed in `public.staff`.
- **Day shape:** 10 sessions. Session 1 (8:20–8:50) is the whole-group morning session with the social story and the morning survey; session 10 (2:05–2:35) is the whole-group afternoon debrief with the afternoon survey; sessions 2–9 are half-periods for group sessions, independent electives and individual sessions. Students go to recess and lunch as normal and come back to **the Hub** (the room's name).
- **Two-day rotation:** the room alternates group-session rotations, so students on Day 1 and Day 2 share group sessions. Every core group session must be done within the student's two days, so **each group session and each independent module must stand alone**: there's no guaranteed order.
- **Group sessions** (max 5 students, 1 staff member; run sheets in `RP.GROUP_SESSIONS[].guide`, slides in `.slides` for the Present view): Rotation A: T-RED Values, RIOT 1, Wellbeing, Chain Analysis. Rotation B: Student Code of Conduct, RIOT 2, Classroom Expectations, Self-Regulation. Both at 8:50, 9:55, 11:23 and 12:26. T-RED is staff-led discussion of the values, **no practical activities** (the presentation's games were for orientation day). RIOT, Wellbeing and Self-Regulation will be rebuilt from the RIOT materials when staff upload them. Use made-up examples; never ask a student to share their own incident.
- **Individual sessions** are dragged into a slot by the teacher (kind `one_to_one`, `RP.INDIVIDUAL_SESSIONS`): Day 1 review of plans, goals and Sentral; Day 2 success plan; classwork and assessment check-in; learning and support check. One student at a time: the plan editor and board warn about clashes. The staff member is whoever is on the run sheet's staffing for that session (`public.staffing`). Each has a page showing the student's relevant surveys and module answers; the success plan prints a Return to Class Plan to sign. Session notes and testing results stay in Sentral and other school systems, not here.
- **Movement breaks** (boxing, circuits…) are on hold while the staff work out how to run them. They stay in the plan editor palette but aren't in the rotations or core.
- **Surveys** (`js/surveys.js`): start and end of both days (`d1am`, `d1pm`, `d2am`, `d2pm`) plus a follow-up 4–6 weeks after return (a "followup" program that reactivates the code for the survey only). Same 10 rating statements in each, from the school's TRHS survey. Surveys done at the same time must take the same time (both mornings match, both afternoons match). Wording asks students not to give identifying information. Ratings go in the session's `result` (`survey`, `ratings`, `total`), written answers in `state.responses`; the Reports page and downloads use them.
- **Pause:** a program can be paused (student absent); the code shows a "paused" screen until resumed.
- **Reading levels 1–5** (Stages 1–5, labelled "Level" not "Stage"): students choose one per module; it's saved in the result for staff. Items give `easy` text for levels 1–2, `more` for 4–5, and modules a `deeper` question for level 5; level 1 reads each page aloud. Every page has a Read aloud button.
- **Chromebooks:** students log in as themselves and use Chrome. They can't print, so certificates and answers offer Save as PDF and Email.
- **Videos** must suit students (Years 7–10, mostly 7–8), not adults. Staff should preview each one before students use it; every video item has a written summary in case it won't play.
- **Electives are done independently** on the laptop, so the teacher is free for 1:1s. Group sessions tell students to put the laptop aside; the teacher ticks them off.
- A finished elective can't be redone unless the teacher clicks **Let them redo**.
- **Records kept for returning students:** electives finished, level and score, group sessions done.
- **Written answers go to the teacher once submitted.** `write` and `select` answers stay on the laptop while the student works, then are saved with the module when it's finished (`sessions.state.responses`), locked, and shown on the student's certificate page and the teacher's record page. Students are told their teacher will read them. Prompts stay optional, as the staff notes ask not to force disclosure.
- **Certificates can be reopened** by the student from their plan, and reprinted by teachers. Names are typed at print time and never saved.
- **Independent modules** are as interactive as possible and vary activity types across the day (sort, order, match, select, rating, sliders, body map, choose-your-path stories, phrase tiles, breathing, chain-writing, video). `module-1`…`module-6` are the reflection halves of the school's module documents; `my-chain`, `tred-values` and `code-of-conduct-check` are built from the school's Chain Analysis video, T-RED presentations and the Department's Student Code of Conduct. Staff-chosen extras: Say It Better, Online Conflict and Social Media, Restorative Conversation Prep, Growth Mindset, Goal Builder, Healthy Habits Check, Asking for Help, Study Skills. Literacy is four modules (Reading, Vocabulary, Spelling and Punctuation, Grammar and Sentences), each with levels 1–5 sized for one session. Numeracy waits for The Daily Dash; pull from there when staff say. Keep the school's wording when editing modules.
- **Branding:** colours from the school's colour hierarchy (maroon, light blue and dark navy primary; royal blue secondary; greys). The colour hierarchy image is a palette guide only: **never use it as a logo or picture on the site.** The logo is the sun rising over an open book (`RP.logo`, drawn as SVG). Motto: "Focusing on our Future" (footer, certificates, Present view). Navy top bar; dashed sunbursts (`img/sunburst.svg`) as soft background decoration.

## Before publishing

- Run the flows in a browser with `?demo=1` (teacher creates a student, plans the day, student completes an elective and gets the certificate). Check every answer in new elective content yourself.
- Changes to the database go in a new SQL file under `supabase/` (e.g. `update-2.sql`) for staff to run in the SQL Editor; keep `schema.sql` as the full current setup. The site must keep working before an update is run (see `withV2` in `js/api.js`).
- Publishing: commit to `main` on `jasefreters/TRHS`. Bump the `?v=` number on every script and stylesheet tag in `index.html` and `teacher.html` so browsers load the new files straight away.
