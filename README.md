# Reset Program

Thomas Reddall High School's two-day Reset Program (pre- and post-suspension), run in the Hub. Each student has a Chromebook for the day. The website shows them their plan and walks them through it, so one staff member can run group and individual modules for up to five students at once.

Everything in the day is a **module**:
- **Group modules:** a staff member with the group, laptops to the side.
- **Individual modules:** either **independent** sessions (on the laptop, at the student's own pace) or **teacher-led** sessions (one-on-one with a staff member).

**Live site:** https://jasefreters.github.io/TRHS/

- Student view: `index.html`
- Teacher dashboard: `teacher.html` (or click **Teacher** in the corner of the student view)

## How a day works

1. **Set up a student.** On the dashboard, click **New student**. The website makes an 8-character code such as `K7Q3-M2XD`. Write it next to the student's name on your offline list; the website never stores names.
2. **Fill in their daily schedule.** Each day has 10 sessions (below). Group modules come from the room's rotation; the rest start empty. Drag independent modules and **teacher-led sessions** onto the empty sessions, or click one and then click a session. Click 👁 to preview a module: **Try it as a student** runs it exactly as students see it (nothing is saved), and **Questions and answers** lists every page with the answers. Changing a group module asks "Are you sure?" first. The schedule warns if two students have a teacher-led session at the same time, and reminds you about each day's review or return plan.
3. **Staffing.** On the **Run sheet**, type who's running each session. Whoever is on for a session runs any teacher-led session in it. Print the run sheet for the day.
4. **Hand over the laptop.** Click **Student view on this laptop**. This logs you out of that laptop only and opens the student's plan. (Or the student types their code.)
5. **The student follows the plan.** The left pane shows the day, with the current session marked "Now" and a tick next to each finished part.
   - Morning session: social story, then the morning check-in: a ready-to-learn traffic light, whether they've had breakfast and have a pen, uniform, bag, lunch and other food, then a short survey.
   - Group modules: laptops to the side.
   - Independent modules: on the laptop, with a **Read aloud** button on every page. Finishing one shows their answers, which they can save as a PDF or email. Only Literacy has reading levels (1–5).
   - **What does it mean?** in the top bar looks up any word (select it on the page, or type it).
   - Breaks: go to B1 and B2 as normal, back to the Hub afterwards.
   - Afternoon debrief: the afternoon survey, then their **certificate for the day**, listing every module they finished. They can reopen it from their plan.
6. **Follow along.** The dashboard updates live: each student's ready-to-learn traffic light and anything they don't have (breakfast, lunch…), their sessions, results, missing core group modules, **I need help** requests and who's staffing now. Tick a group module done for everyone in one click, and **Present** it on the projector. Open a teacher-led session to see the student's surveys and module answers; **My Return Plan** and the **Return from suspension meeting** print the **Student Return to Class Plan** to sign, filled in from what the student ticked and wrote in My Return Plan.
7. **Day 2 and finishing.** Click **Move to Day 2** the next morning. **Pause** a program if a student is away. **Finish program** turns the code off. The record stays.
8. **Follow-up.** About 4–6 weeks after they return, open the student's record and click **Start follow-up survey**. Their code works again for the survey only.

Every session ends with a school bell or in the middle of a period. To change a day's times (for example Tuesday's shorter bell times, or a shorter session), click **⏱ Times** on the daily schedule; you can apply the new times to everyone in the program that day. In the same box, **＋** adds a session after another (it splits that session's time in half, so you can make three 20-minute sessions in a period instead of two) and **✕** removes a break or a session that hasn't been started (for example, B2 and P5 on a short day: the afternoon debrief moves to the last session left). New sessions start empty.

**Group modules** run on a two-day rotation, so every student gets all eight across their two days whichever day they start. Each stands alone, and each follows the **Thomas Reddall Lesson Routine**: entry, Do Now, learning intention and success criteria, explicit teaching, brain break, application (butcher's paper, discussion, card sorts), recap, exit.

Run sheets and projector slides for each are on the dashboard's **Session guides** page, with the lesson routine and written **movement breaks** to pull out when students need one. Wellbeing and Self-Regulation are still outlines.

**Teacher-led sessions:** *Teacher-led: My Reset Plan* (Day 1), *Teacher-led: My Return Plan* (Day 2), *Return from suspension meeting*, *Classwork and assessment check-in*, and *Learning and support check*. Put the independent **My Reset Plan** or **My Return Plan** before its teacher-led session: the session page shows what the student wrote.

**Understanding Truancy** is a teacher-led module the student works through on their laptop while you sit with them. Open it from their daily schedule or the board: your page shows each answer as they type, with a "Talk about it" prompt for each activity, a reminder of what to look up in Sentral, and a staff check-in you can print (it isn't saved).

**Optional group module:** *RAGE Recap* can replace another group module when it suits the group.

**Other:** drag **Other** onto a session and type what it is (for example "Sport with Mr B"). The student sees it and is told they won't need their laptop.

**Morning session and afternoon debrief:** drag either to a different time, for example if a student arrives late or has a return meeting.

**RIOT** has eight lessons, each condensed to 25 minutes. On the daily schedule, choose the lesson and how students do the worksheet: on **paper**, as a **PDF on their laptop**, or **interactive on their laptop**. Changing one student offers the same for everyone else in that RIOT session. Click **Present** to show the lesson slides; every worksheet exercise has a matching slide. Session guides has each lesson's run sheet, slides, worksheet, PDF and **answers** (with **Print answers**).

If no staff member is free, students can do a RIOT lesson on their own: with a laptop format they see the lesson slides beside their worksheet (they can hide them or open them in a new tab), and the slides follow the exercise they're on. You can turn the slides off for a session on the daily schedule (**No slides for students**). You can also drag a lesson from **RIOT lessons** on the daily schedule into an independent session; finishing one counts as the core RIOT module.

**Following answers live:** for any module a student has started, click **Answers** on the daily schedule (or **See answers** on the board) to see what they've written so far. Notes and testing results stay in Sentral and the school's usual systems.

## Independent modules

All of these stand alone and can be done in any order:

- **Modules 1–5:** the reflection halves of the school's module documents.
- **My Reset Plan** (the Behaviour Chain Analysis worksheet; a printable copy is in [`resources/`](resources)) and **My Return Plan**: done before the teacher-led versions.
- **Suspension Booklet:** students choose a subject (Maths, English, Drama, Science, History, Geography, PDHPE, TAS, RIOT, Wellbeing), use the booklet on screen, a paper copy or their own, and type their answers. The day certificate lists the subjects they started and finished. The Year 7 booklet is split by subject in [`booklets/year7/`](booklets/year7) without the teacher answer sheets. To add another year, split its booklet the same way and add it to `books` in [`js/modules/suspension-booklet.js`](js/modules/suspension-booklet.js).
- **My Chain** (chain analysis), **T-RED Values in Action**, **Code of Conduct Check**.
- **Say It Better**, **Online Conflict and Social Media**, **Restorative Conversation Prep**, **Growth Mindset**, **Goal Builder**, **Healthy Habits Check**, **Asking for Help**, **Study Skills**, **Attendance and Truancy**.
- **Friendships:** healthy friendships, support networks and talking to friends.
- **Literacy:** one half-hour module with levels 1–5 (NSW Stages 1–5): a reading passage and questions, then vocabulary, spelling and punctuation, and grammar.
- **Numeracy: Day 1** and **Numeracy: Day 2**, about 30 minutes each. Each level is an NSW Stage: Level 1 = Stage 1 (Years 1–2) up to Level 5 = Stage 5 (Years 9–10). Levels 2 and 3 come from [The Daily Dash](https://jasefreters.github.io/mathswarmup/). To refresh the Dash questions, check out the Dash next to this repo and run `node tools/dash-numeracy.js ../mathswarmup`.

**Videos** (in Module 2, My Chain and Growth Mindset) are YouTube clips chosen by title and channel. Preview each one before students use it, and change any in its module file. Each has a written summary underneath in case it won't play.

## Surveys and reports

Students do a short survey at the **start and end of each day**, and a **follow-up** a few weeks after going back to class. Every survey has the same 10 rating statements from the school's TRHS survey (score out of 50), plus a few written questions. Surveys done at the same time are the same length, so Day 1 and Day 2 students finish together.

The **Reports** page shows, for any date range (for example a term):
- programs started and finished
- % who did the first and last survey
- average Day 1 start → Day 2 end scores and the change
- the change per statement and the most improved areas
- each student's scores, including the follow-up
- what students found most helpful, and what extra support they asked for

**Download summary** and **Download all survey responses** give spreadsheets.

## Records

**All students** lists everyone who has been through the program, with their group modules and individual sessions. Search by code, filter by year, status or date, **Download spreadsheet** (one row per program), or **Delete old records** (for example at the end of the year). Click a student for their record:

- **Each program:** shown day by day, with their written answers and surveys and the reading levels they chose.
- **Edit program:** opens the plan editor. **Mark done** records an elective done another way. **Let them redo** clears one.
- **Print certificates** (one per day, optionally with their answers) and **Print program record**. You type the name when printing; it isn't saved.
- **Pause / Resume**, **Reopen**, **Start a new program**, **Start follow-up survey**.
- **Delete program** removes one program. **Delete student** removes everything about a student; you confirm by typing their code.

## Changing things

- **Timetable, lesson routine, group modules (guides and slides), movement breaks, rotations, teacher-led sessions, default modules:** [`js/config.js`](js/config.js).
- **Surveys:** [`js/surveys.js`](js/surveys.js).
- **Words students see** (social stories, group, debrief and break messages, free choice): [`js/content.js`](js/content.js).
- **Modules:** one file each in [`js/modules/`](js/modules). Copy an existing one, give it a new `id`, and add a `<script>` line for it in both `index.html` and `teacher.html`. A module has either `items`, or `levels` (each with `items`). Add `score: false` for reflection modules. Item types:
  - `read`: a page of text (`title`, `text`)
  - `mc`: multiple choice (`q`, `choices`, `answer` = index of the right choice, optional `explain`)
  - `input`: type an answer (`q`, `answer`, optional `accept`, `prefix`, `suffix`, `text: true` for a word answer)
  - `sort`: tap cards into groups (`q`, `buckets`, `cards` with the right `bucket`)
  - `order`: put cards in order (`q`, `cards` in the right order)
  - `match`: drag or tap each answer onto its match (`q`, `pairs` of `left` and `right`)
  - `select`: choose what fits you (`q`, `options`, optional `pick`, `other: true`)
  - `write`: the student's own answers (`title`, optional `q`, `prompts`; `chain: true` draws them as linked steps)
  - `slider`: rate on sliders (`sliders` with `label`, `min`, `max`, `left`, `right`, `unit`)
  - `bodymap`: tap where on the body you feel it (`q`)
  - `story`: choose-your-path (`start`, `nodes` with `text` and `choices`, or `end: "good"`/`"bad"`)
  - `tiles`: build a sentence from word tiles (`parts`: text and `{ options }`; an option can have a `warn` message)
  - `video`: a YouTube clip (`youtube` id, `text` summary)
  - `scale`: a quick check-in, not saved (`q`, `labels`)
  - `rating`: rate statements 1–5 (surveys)
  - `breathe`: guided box breathing

  **Levels:** only modules with `levels` (Literacy) ask for a level. Within them, items can have `easy` (replacement text for levels 1–2) and read items `more` (extra detail for levels 4–5).

  Answers stay on the laptop while the student works, then are saved with the module when it's finished, locked, and shown to the student and to staff on the record.

Text can use `**bold**`, blank lines between paragraphs, `- ` at the start of a line for lists, and `[text](https://link)`.

Modules are kept to about 20 minutes. Pages marked `extra: true` are skipped unless you choose **Full version** on the daily schedule. In Literacy and Numeracy, students who finish a level are offered the next one.

Updating the site: commit to `main`, and bump the `?v=` number on the script and stylesheet tags in both HTML files so browsers load the new files straight away.

## Trying it out

Open the site with `?demo=1` on the end (for example `teacher.html?demo=1`) to use a pretend database that lives only in that browser. Any email and password log in. `?demo=0` turns it off. Add `&time=10:00` to see the day as it looks at a different time.

## Privacy

- No names or personal details are stored. Students are random codes; the code-to-name list stays offline with staff.
- Students don't log in. Their code only opens their own plan, and only while their program (or follow-up) is open.
- Teachers log in with their own Supabase accounts. Only emails on the staff list can see anything.
- The database stores session ticks, scores and Literacy levels, written answers from finished modules, the morning ready-to-learn check, and survey answers, all linked to the code only. Students are told their teacher reads their answers, and survey and module questions ask them not to write names or identifying details. Everything is deleted with the program or the student, or with **Delete old records**.
- Staff names typed on the run sheet are stored so the dashboard can show who's running each session.
- **What does it mean?** sends only the word being looked up to a free online dictionary (dictionaryapi.dev), nothing about the student.
- This repository and the website are public, so never put student information in them.

## Setting up

1. Create a Supabase project in the Sydney region.
2. In **SQL Editor**, run [`supabase/schema.sql`](supabase/schema.sql) with the teachers' emails in its last lines.
3. Under **Authentication**, turn off new sign-ups and add each teacher as a user (with **Auto confirm**).
4. Put the project URL and publishable key in `js/config.js`.
5. In GitHub, go to **Settings → Pages**, set **Source** to *Deploy from a branch*, choose `main` and `/ (root)`, and save.

**Database updates:** if your database was set up before staffing, pause and follow-up surveys were added, run [`supabase/update-2.sql`](supabase/update-2.sql) once in a new SQL Editor query, then [`supabase/update-3.sql`](supabase/update-3.sql) (changing session times, and RIOT worksheets on laptops). The dashboard shows a reminder until they're done.

**Adding a teacher:** create them under **Authentication → Users** (email, password, Auto confirm), then paste [`supabase/add-staff.sql`](supabase/add-staff.sql) into a new SQL Editor query, put in their email and run it. Each teacher logs in with their own email; logging out on one computer doesn't affect others.

## Sentral post

On a student's record (**All students**, then the student), **Sentral post** writes a short overview for the Sentral staff noticeboard, in plain words for staff who don't know the program: a few lines on how the program works (you can leave these out; edit the wording in `sentralIntro` in [`js/content.js`](js/content.js)), what the student did, their surveys put together, and one of their own responses. Type their name, choose what to include, check the wording, then **Copy** and paste it into Sentral. Nothing typed there is saved.

## Certificates

Students get a certificate at the end of each day (after the afternoon survey), and a **completion certificate** for the whole program after the Day 2 afternoon survey. Staff can print any of them from the student's record (**Print certificates**): tick the day certificates, the completion certificate, or both.
